## Role and context

You are working on **FinLens**, a Flutter personal-finance app. Read
[`CLAUDE.md`](CLAUDE.md) and [`claude/CODEBASE_MAP.md`](claude/CODEBASE_MAP.md) first.

Every figure that adds up more than one account passes through one function, and
that function has a hole in it:

```dart
static double toBase(double amount, String currency) =>
    amount * (_perUnit[currency] ?? 1.0);
```

`_perUnit` is a compile-time table of **six** codes. Anything else — a Bosnian mark,
a Turkmen manat added by the user, any of the other ~170 ISO codes — converts at
**1.0**. On a real screen that reads: an account holding `BAM 2,000` contributes
**$2,000** to `ASSETS`. Not an approximation — a different number, presented with the
same confidence as the correct ones. `CurrencyDef`'s own doc says custom currencies
get no rate at all.

The table is also unreachable: the rates are constants in a source file, so a user
whose currency moved 30 % this year has no way to say so, and `TRY: 0.031` will be
wrong forever.

### The rules this task implements

> **1. A rate is data the user owns**, kept per currency against the reporting
> currency, entered as `1 <reporting> = X <currency>`, and used until changed.
>
> **2. A total that cannot be computed is not shown.** No fallback, no guess: if any
> account or entry inside a total has no rate, the total is replaced by a warning
> that leads to the rate.

### What the user sees

| Where | Before | After |
|---|---|---|
| Currencies screen | code + format preview | code + **rate**, with the date under it |
| Currency edit sheet | symbol / position / decimals | **Rate** first, then those, then the preview |
| `ASSETS` with an unrated account | a wrong number | `Rate missing`, and a card that sets it |
| A group, net worth, IN / OUT | a wrong number | the same, wherever the unrated account or entry reaches |
| A rate entered | — | every total returns, unchanged in shape |

## 0 · The design, verbatim

### 0.1 The rate table and its fallback

```dart
abstract final class Fx {
  /// Value of one unit of each currency, expressed in USD (USD == 1.0). This is
  /// the fixed rate table only; the *display* base is chosen per store and
  /// supplied to [convert]/[toBase] by the caller.
  static const _perUnit = <String, double>{
    'USD': 1.0,
    'EUR': 1.10,
    'GBP': 1.28,
    'TRY': 0.031,
    'TMT': 0.286, // Turkmen manat (official peg ≈ 3.5 TMT/USD)
    'JPY': 0.0067,
  };

  static double rate(String from, String to) {
    final f = _perUnit[from] ?? 1.0;
    final t = _perUnit[to] ?? 1.0;
    return f / t;
  }

  static double toBase(double amount, String currency) =>
      amount * (_perUnit[currency] ?? 1.0);

  static double convert(double amount, String from, String to) =>
      amount * rate(from, to);
}
```

### 0.2 The store's one conversion point, and what stands on it

```dart
  /// base-currency conversion for the store's own aggregates: convert [amount]
  /// from [currency] into the current [baseCurrency]. A thin instance wrapper so
  /// [Fx] stays a pure function of its inputs and every call site reads the live
  /// base (nothing caches it).
  double _toBase(double amount, String currency) =>
      Fx.convert(amount, currency, baseCurrency);
```

```dart
  /// Balance converted to the base currency — the only form safe to add up
  /// across accounts (spec 3.4 FX rule).
  double balanceInBase(String accountId) => _toBase(
        balanceOf(accountId),
        accountById(accountId)?.currency ?? baseCurrency,
      );

  double groupTotal(AccountGroup group) => accounts
      .where((a) => a.group == group)
      .fold(0.0, (sum, a) => sum + balanceInBase(a.id));

  double get totalAssets => AccountGroup.assets
      .fold(0.0, (sum, g) => sum + groupTotal(g));

  /// Positive magnitude of what is owed.
  double get totalLiabilities => AccountGroup.liabilities
      .fold(0.0, (sum, g) => sum + groupTotal(g))
      .abs();

  double get netWorth => totalAssets - totalLiabilities;
```

## 1 · Rates become store data

**1a. One number per currency, against the reporting currency.**

```dart
  /// How many units of a currency one unit of [baseCurrency] buys — the
  /// direction rates are quoted out loud ("the dollar is 40 lira") and the one
  /// that keeps its digits for weak currencies: at four decimals, 40.1250 loses
  /// nothing, while its reciprocal 0.0249 has already lost two places.
  ///
  /// The base currency is not in the map; its rate is 1 by definition. A code
  /// that is absent has **no rate** — that is a state, not a zero (§2).
  Map<String, double> get snapshotRates => …;

  double? rateFor(String code);     // null when unknown; 1.0 for the base
  DateTime? rateSetAt(String code); // when it was last written
  void setRate(String code, double rate);  // rejects <= 0, stamps the date
```

- Stored with 6 decimals, shown with up to 4, trailing zeros trimmed (`3.5`, not
  `3.500000`).
- `<= 0` is refused at the store, not only in the UI: a zero rate silently zeroes an
  account's whole balance.
- Persisted the same way `baseCurrency` is (explore step 4), including the date.

**1b. `Fx` stops owning the table.** Keep `Fx` as the pure maths, but its inputs come
from the store:

```dart
  /// Pure conversion given the two rates, so the table can live in the store and
  /// [Fx] stays testable without one. Null in, null out.
  static double? convertWith(double amount, double? fromRate, double? toRate);
```

The existing `_perUnit` table is **seeded into the store** on first run (§5) rather
than deleted outright — those six numbers are the only starting point a user has, and
`TMT: 0.286` is a peg they may well keep. Report where you put the seed and why.

**1c. The store's wrapper becomes honest:**

```dart
  /// Null when [currency] has no rate — the caller must decide what to show, and
  /// `?? 1.0` is exactly the bug this task removes.
  double? _toBase(double amount, String currency);
```

## 2 · A total that cannot be computed is not shown

Follow explore step 2's list, and treat its three kinds differently:

**2a. Totals the user reads become nullable.** `balanceInBase`, `groupTotal`,
`totalAssets`, `totalLiabilities`, `netWorth`, the spendable card, the Ledger's
`IN` / `OUT` / `LEFT`, Insight's aggregates: each returns `double?`, and each is null
when **any** account or entry inside it has no rate. Not "skip the unrated ones" —
a total with a piece missing is not the total, and a quietly smaller number is the
same lie in a different direction.

**2b. Per-row displays keep their own currency.** An account row already shows
`BAM 2,000`; a Ledger row already shows its own amount. Those are known numbers and
do not change. Only the sums go quiet.

**2c. Every silenced figure renders `curRateMissing` in `AppColors.warning`,** at the
size and position the number had, and the screen that owns the total shows the card
from §4b beneath it. Do not shrink or re-lay-out the surrounding card; the warning
takes the number's slot.

**2d. Intermediates** (a conversion used to sort, to compute a percentage, or to pick
a colour) must not crash. Where an intermediate is null, that row's derived figure is
omitted with the same rule, and the ordering falls back to the native amount.
Report every such site and what you chose.
